# Установка найденных пиров в конфигурацию Yggdrasil

Дата: 2026-11-24
Статус: на утверждении

## Зачем

PeerYgg находит самые быстрые живые пиры, но применить результат можно только руками:
`-output config` печатает список через запятую, и пользователь сам копирует его в
`Peers` в конфиге yggdrasil. Нужен флаг, который сам вписывает найденные пиры в
конфиг, обязательно сохраняя бекап исходного файла.

Заготовки в коде уже есть и не используются: `Config.AddCmd`, `Config.RemoveCmd`,
`Config.DryRun` (`internal/config/config.go:41-43`) и `peer.Diff`
(`internal/peer/peer.go:144`).

## Цели

- `-install` заменяет `Peers` в конфиге yggdrasil на выбранные пиры (`selected`,
  то есть top-N плюс добавки по `-country`).
- Перед изменением всегда создаётся бекап конфига рядом с оригиналом.
- Изменяется только значение `Peers`. `PrivateKey`, `PrivateKeyPath`, `Listen`,
  `AdminListen`, `InterfacePeers`, `MulticastInterfaces` и прочее не трогаются,
  комментарии и форматирование HJSON сохраняются.
- Сервис не перезапускается автоматически: печатается готовая команда рестарта.

## Не-цели

- Поддержка OpenWrt с текущим пакетом (netifd): там нет `yggdrasil.conf`, источник
  правды — UCI `/etc/config/network`. При обнаружении такого окружения — внятная
  ошибка с объяснением, без попыток записи.
- Управление `InterfacePeers`.
- `yggdrasilctl addPeer/removePeer` — изменения эфемерные и теряются при рестарте,
  поэтому не используются.
- Автоматический рестарт сервиса (systemd/launchd/openrc/Windows SCM).

## Факты, на которых стоит дизайн

Проверено по исходникам yggdrasil-go (0.5.x) и упаковкам:

1. Демон **не читает конфиг по умолчанию**. Путь задаётся юнитом/пользователем через
   `-useconffile <path>`. Значит путь надо угадывать по списку кандидатов под GOOS,
   с явным override.
2. Пути:
   - Debian/Ubuntu `.deb`: `/etc/yggdrasil/yggdrasil.conf` (group `yggdrasil`, `0640`)
   - Arch, Fedora/RPM, macOS `.pkg`, generic Linux, OpenRC, busybox-init: `/etc/yggdrasil.conf`
   - FreeBSD port: `/usr/local/etc/yggdrasil.conf`
   - Entware (в репозитории пакета конфига нет, это конвенция): `/opt/etc/yggdrasil.conf`
   - Windows MSI (сервис `Yggdrasil`): `%ProgramData%\Yggdrasil\yggdrasil.conf`
3. Формат — HJSON (JSON тоже принимается). `Peers` — массив строк-URI:
   `tcp://`, `tls://`, `quic://`, `ws://`, `wss://`, `socks://`, `sockstls://`,
   `unix://`. `Result.Peer` уже содержит полный URI из nodes.json — писать можно как есть.
4. Перечитывания по SIGHUP нет с 0.4.0 (SIGHUP убивает процесс). Единственный
   надёжный способ применить — полный рестарт сервиса. `systemctl reload` не использовать.
5. Файл обычно `0640` и принадлежит root (Debian: `root:yggdrasil`). Значит запись
   требует sudo, а после записи нужно сохранить владельца и режим.

## Подходы

**A. Точечный патч блока `Peers` в тексте + бекап + без рестарта (выбран).**
Ноль зависимостей, комментарии и порядок ключей сохраняются, работает с HJSON и JSON
входом. Риск — надо корректно найти границы массива с учётом строк и комментариев;
закрывается собственным сканером и проверкой через `yggdrasil -normaliseconf`.

**B. Парсить HJSON через `github.com/hjson/hjson-go` и пересобирать файл.** Просто, но
уничтожает комментарии и форматирование, добавляет первую внешнюю зависимость в
проект (сейчас `go.mod` пустой) и при малейшем рассинхроне структуры молча роняет
поля в дефолты. Отклонён.

**C. Только `yggdrasilctl addPeer`, без записи файла.** Изменения живут до рестарта —
не выполняет требование «установить в конфигурацию». Отклонён как основной вариант.

**D. Поддержка UCI/OpenWrt.** Отдельная задача с другим источником правды; сейчас
только явная ошибка. Отложено.

## Дизайн

### CLI

```
-install              записать выбранные пиры в конфиг yggdrasil
-config PATH          путь к конфигу (иначе автоопределение)
-dry-run              показать, что изменится, ничего не писать
```

Env: `PEERS_CONFIG` как путь по умолчанию, `DRY_RUN=1` (поле уже есть в `Config`).

`-install` совместим с `-n`, `-country`, `-country-count`, `-group`;
записывается ровно то, что попало в `selected`. `-install` и `-output` не конфликтуют:
вывод в stdout остаётся как есть, установка — дополнительный шаг после вывода.

### Определение пути (`internal/yggconf/detect.go`)

Порядок: `-config`/`PEERS_CONFIG` → существующий файл из списка кандидатов для GOOS.
Кандидаты для linux/darwin: `/etc/yggdrasil/yggdrasil.conf`, `/etc/yggdrasil.conf`,
`/opt/etc/yggdrasil.conf`, `/usr/local/etc/yggdrasil.conf`. Windows:
`%ProgramData%\Yggdrasil\yggdrasil.conf`. Если ни один не найден — ошибка со списком
проверенных путей и подсказкой `-config`.

Если на Linux/macOS есть `/lib/netifd/proto/yggdrasil.sh` или конфиг не найден, но
в `/etc/config/network` есть `option proto 'yggdrasil'` — ошибка «OpenWrt управляет
yggdrasil через UCI, правьте /etc/config/network». Ничего не пишем.

### Патч `Peers` (`internal/yggconf/patch.go`)

`ReplacePeers(data []byte, peers []string) (out []byte, old []string, err error)`

Сканер по байтам ведёт состояние: обычный текст, строка (`"`/`'`, с `\`), line-comment
(`//`, `#`), block-comment (`/* */`), глубина `{}`/`[]`. На глубине 0 ищется ключ
`Peers` (в кавычках или без), далее `:` и значение-массив. Границы массива — парные
`[`/`]` с учётом тех же состояний. Заменяется только диапазон `[ ... ]` включительно:

```
Peers: [
  tcp://edge1.example.net:443
  tls://edge2.example.net:443
]
```

Отступы повторяют отступ строки с ключом + два пробела, по одному URI на строку,
запятые — как в исходнике (если в исходном массиве были запятые, ставим их; иначе
без них, как в официальных примерах). Старые значения возвращаются для отчёта и для
`peer.Diff`.

Особые случаи:
- ключа `Peers` нет — блок добавляется в конец файла (HJSON допускает корневой объект
  без фигурных скобок);
- файл в JSON (`{ "Peers": [...] }`) — тот же патч, ключ в кавычках;
- несколько вхождений `Peers` на глубине 0 (в `InterfacePeers` глубина > 0, не
  считается) — ошибка, ничего не пишем;
- CRLF сохраняется;
- пустой массив и `Peers: []` — валидный случай;
- синтаксис не распознан — ошибка без записи.

### Бекап (`internal/yggconf/backup.go`)

`<conf>.bak-YYYYMMDD-HHMMSS` в той же директории; если имя занято — суффикс `-2`, `-3`.
Пишется точная копия байтов исходника, права копируются с оригинала (`0640`), владелец —
через `os.Chown` при наличии прав. Существующий бекап никогда не перезаписывается.
Бекап создаётся до любой записи в конфиг; если бекап не удался — установка прерывается.

### Запись (`internal/yggconf/install.go`)

Временный файл в той же директории → `Chmod`/`Chown` как у оригинала → `os.Rename`
поверх (на Windows при ошибке rename: удалить и переименовать, бекап уже есть).
`os.Rename` в другую ФС не используется, поэтому запись атомарна на Unix.

Проверка до подмены: если `yggdrasil` найден в PATH — прогнать
`yggdrasil -normaliseconf -useconffile <tmp>`; ненулевой код или ошибка парсинга —
установка отменяется, временный файл удаляется, конфиг не тронут. Если бинаря нет —
проверка пропускается с предупреждением в stderr.

Ошибки прав (`EACCES` при чтении/записи) — сообщение с подсказкой запустить через `sudo`.

### Отчёт

В stderr: путь конфига, путь бекапа, `+N / -M` пиров (через `peer.Diff`), команда
рестарта под текущую ОС:
systemd `systemctl restart yggdrasil`, macOS `launchctl kickstart -k system/yggdrasil`,
FreeBSD `service yggdrasil restart`, Windows `Restart-Service Yggdrasil`,
OpenRC `rc-service yggdrasil restart`. Если определить не удалось — общая подсказка.

`-dry-run` печатает то же, но без бекапа и записи.

## Тесты

- `patch_test.go`: фикстуры — многострочный HJSON с комментариями внутри массива,
  inline-массив в одну строку, JSON-вход, CRLF, отсутствующий `Peers`, пустой массив,
  закомментированный `# Peers:` (не должен считаться ключом), `InterfacePeers` с
  вложенными массивами (не должен пострадать), дубликат ключа → ошибка.
- `backup_test.go`: имя с timestamp, отсутствие перезаписи, сохранение прав.
- `install_test.go`: полный цикл на `t.TempDir()` с фикстурой конфига; проверка, что
  прочие поля и комментарии на месте, бекап побайтово равен исходнику, права сохранены.
- `detect_test.go`: подстановка кандидатов, приоритет `-config`, ошибка при отсутствии.
